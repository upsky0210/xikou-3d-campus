# 新增老師 NPC（溪口國小 3D 校園）

使用者是學校老師兼資訊管理員，常常一次丟一張老師照片＋一行說明，例如：

> 教師NPC 林老師/五年三班 對話：(偏正向鼓勵) 小遊戲：數學 因數與倍數 地點 五年三班

目標是做到「上線、可以玩、檢查通過、紀錄寫好」，中間不用一直問；只有真的看不清楚或資訊衝突才問。回覆一律台灣正體中文、台灣用語。

## 0. 先記住的規則（每一條都有理由）

- **照片只當參考，絕對不放進 `site/`**（`site/` 會整個公開到 GitHub Pages；老師、小朋友的照片是個資）。
- **只做照片裡看得到的東西**。看不清楚的（鞋子沒拍到、下半身被擋住）用中性的預設，並在回報裡說「照片沒拍到，先用預設」；不要自己加刻板印象的裝飾（書法掛軸、算盤之類）。太小做不出來的（手錶、耳環）直接說沒做。
- **不要把老師的 email、電話放進程式**（公開網站）。
- **班級代號 ≠ 教室編號**：`campus-data.js` 裡 `code: '503'` 是「五年三班」，`no: '415'` 是教室門牌。使用者說「五年三班」就找 `code === '503'`。
- 小修改改好、驗證過就直接 commit＋push，不用再問（使用者說過）。

## 1. 位置

在 `site/js/campus-data.js` 找房間：`R('3F', 'C', [x1, y1, x2, y2], { no, code, name, type, doors })`。第二欄是哪一棟（A 敬業樓、B 至善樓、C 勤學樓、D 思源樓），`doors` 是門在哪一面。

NPC 的位置寫在 `places`，`at()` 回傳 `[x, z, yaw]`（公尺）。yaw：`0`＝面向北（-z）、`Math.PI`＝面向南、`-Math.PI / 2`＝面向東、`Math.PI / 2`＝面向西。

常用的寫法（照同一棟、同一排已經有的老師抄最安全）：
- 勤學樓（C）班級，黑板在西、學生在東：`[r.m.x1 + 1.3, r.cz - 0.8, -Math.PI / 2]`
- 思源樓（D）班級，黑板在南：`D_CLASS_FRONT(r)`
- 處室、特別教室：先讀 `site/js/furniture.js` 那間的家具函式（例如 `healthCenter2`、`meetingRoom`），站在櫃台或講台旁的走道，不要站進家具裡。`fr.toWorld(u, v)` 的 u／v 方向要看 `frameOf`：門在 N/S 時 u 是東西向（從 x1 量起）、門在 E/W 時 u 是南北向；`away` 是離門那一側。

用 `grep -n "code === '4" site/js/npcs.js` 這類方式找鄰居老師，照抄它的 `at` 再微調。

## 2. 造型（look）

NPC 寫在 `site/js/npcs.js` 的陣列裡。整段格式照下面（從一位現有老師複製最快）：

```js
{
  name: '林老師', title: '五年三班導師', game: 'factor',
  hello: ['🌟 林老師：…', '💪 林老師：…', '😊 林老師：…', '🔢 林老師：要不要來挑戰因數與倍數？'],
  // 註解：在哪一棟、哪一間、站哪裡、面向哪
  places: [{ floor: '4F', where: '五年三班', game: true, at: () => { const r = rooms.find((x) => x.code === '503'); return [r.m.x1 + 1.3, r.cz - 0.8, -Math.PI / 2]; } }],
  look: {
    // 註解：依照片描述髮型、眼鏡、衣服顏色；照片沒拍到、太小沒做的也寫上
    skin, hair, top, pants, shoe, …造型選項…, pal: { … }, face: [16 行 × 16 字],
  },
},
```

造型選項（帽子、髮型、外套、圍巾、條紋、印字 T 恤…）和臉的調色盤字母，查 `references/look-options.md`。要的效果現有選項做不到時，在 `site/js/blocks.js` 加一個新選項（照旁邊選項的寫法，加一行中文註解說明用途），之後別的老師也能用。

臉：16×16 字元。上面幾行是頭髮（瀏海、分線用 `S` 挖出額頭），中間眼睛、眼鏡，下面鼻子、嘴巴。照片在笑、露牙齒就用 `T`；閉嘴微笑而且不要換成張嘴大笑就加 `calm: true`。

## 3. 台詞（hello）

- 3～5 句，每句開頭一個 emoji，格式 `'🌟 林老師：句子'`。
- 使用者給的句子**一字不改**放進去；只給方向（「偏正向鼓勵」「認真學習…等」）就照那個語氣補到 3～4 句。
- 最後一句邀請玩小遊戲：「要不要來玩／挑戰 ○○？」。

## 4. 小遊戲

先看有沒有現成的可以沿用（`site/js/app.js` 的 `GAME_FILE` 列出所有種類和檔案）。要新寫的話，讀 `references/games.md`：裡面有三選一題庫遊戲（`mcGame`，最省事、可以接 Google 試算表題庫）、程式出題、自己的畫面這幾種做法，以及**新遊戲一定要改的 4 個地方**。

題目內容要正確、符合年級：不確定的知識寫保守的說法，並在回報裡請那位老師看一下答案。可以用程式出題的（數學）就寫產生器，再用 node 自動驗算幾萬題。

## 5. 驗證

```bash
cd C:/AI/Claude/3Dmap/site
node tools/bump-version.mjs          # 換版本號（不換的話瀏覽器會用舊檔案）
node tools/check.mjs                 # 全校自動檢查：語法、提示文字、護照名稱、卡住、門、老師位置
```

`check.mjs` 會檢查「每位老師的小遊戲都有提示文字和護照名稱」；沒過就是第 4 步漏改。

接著實際看畫面：內建瀏覽器窗格常常是隱藏的（截圖不會更新），用 `scripts/snap.mjs` 開無畫面 Chrome 截圖：

```bash
node .claude/skills/add-teacher-npc/scripts/snap.mjs shots.json <輸出資料夾>
```

`shots.json` 的格式和「站到老師前面」「按 F 開遊戲」的範例寫在 `scripts/snap.mjs` 開頭。至少截兩張：老師本人（看造型、提示文字）、遊戲第一題。用 Read 看截圖，造型不對就改、重拍。同姓的老師很多（林老師、趙老師、陳老師…），截圖時用 `x.title` 找人，不要只用名字。

看截圖時也檢查字看不看得清楚（按鈕字色）、重要的東西有沒有被別的東西擋住；改完位置或造型要重拍、重走一次，不要拿修改前的截圖回報。沿用現有題庫時把題目讀一遍，有錯就修。

## 6. 上線與紀錄

1. `git add -A && git commit`（訊息寫中文：新老師○老師（○○○）與小遊戲「○○」），`git push`。
2. `node tools/check.mjs --live`：等 GitHub Pages 換成新版本號。
3. `C:\AI\Claude\3Dmap\工作紀錄.md`：在最後一個 `| 11-` 那行後面加一行 `| 日期（星期） | 學校 | 1 | 內容 |`（日期照今天）。這個檔案不在 git 裡。
4. 有新的造型選項、新遊戲檔案、要人工處理的事，寫進 `site/docs/交接.md`。
5. 用 SendUserFile 把截圖傳給使用者。

## 7. 回報給使用者

短短的，分段：
- **位置**：哪一樓、哪一間、站哪裡。
- **造型**：依照片做了什麼；**照片沒拍到、太小沒做的**要明講。
- **台詞**：列出來。
- **小遊戲**：怎麼玩、幾題、題目範圍；程式出題的說驗算了幾題。
- **請確認**：需要那位老師看的地方（題目正確性、進度、造型）。
- 最後一句：檢查通過、線上版本號。

## 8. 這份 skill 有兩份，改了要同步

- 使用中的：`3Dmap/.claude/skills/add-teacher-npc/`（不在 git 裡）。
- 備份：`site/docs/skills/add-teacher-npc/`（跟著 git，學校和家裡的電腦靠它同步；是公開的，不能寫 email、電話、金鑰）。

改了使用中的那份，就複製回備份再 commit：在 `3Dmap` 資料夾執行 `cp -r .claude/skills/add-teacher-npc site/docs/skills/`。pull 下來以後如果備份有更新，反方向複製：`mkdir -p .claude/skills && cp -r site/docs/skills/add-teacher-npc .claude/skills/`。

文中的 `C:/AI/Claude/3Dmap` 是學校電腦的路徑；在別台電腦就換成那台的專案資料夾。工作紀錄的地點欄照實寫「學校」或「家裡」。
