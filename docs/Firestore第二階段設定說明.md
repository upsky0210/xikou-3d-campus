# Firestore 第二階段（老師看進度）— 四項設定操作說明

寫於 2026-11-11。這份文件只放在本機，不會上傳到網站。

做完這四項，我才能做「測試頁」去讀 Classroom 的課程和名單。全部大約 15～20 分鐘。

> Google 的後台選單名稱偶爾會改版，下面寫的是目前常見的名稱。找不到時，用後台最上面的搜尋列搜尋括號裡的關鍵字。

**兩個網域**

| | 網域 | 這份文件的稱呼 |
|---|---|---|
| 老師 | skps.tp.edu.tw | 老師網域 |
| 學生 | st.skps.tp.edu.tw | 學生網域 |

**先準備好一樣東西：OAuth 用戶端 ID**

第 4 項會用到。取得方式：

1. 開 <https://console.cloud.google.com/>，上方專案選 `xikou-3d-campus`。
2. 左邊選單 →「API 和服務」→「憑證」。
3. 在「OAuth 2.0 用戶端 ID」底下，找類型是「網頁應用程式」的那一筆（Firebase 自動建立的，名稱通常是 Web client (auto created by Google Service)）。
4. 複製它的「用戶端 ID」（一長串，結尾是 `.apps.googleusercontent.com`）。

第一階段你在學生網域設「信任」時用的就是這一組。

---

## 第 1 項：兩個網域都允許 App 讀取 Classroom 資料

**老師網域、學生網域各做一次。**

1. 用該網域的管理員帳號登入 <https://admin.google.com/>。
2. 左邊選單 →「應用程式」→「Google Workspace」→「Classroom」。
3. 點「資料存取權」（Data access）。
4. 勾選「使用者可以授權應用程式存取自己的 Google Classroom 資料」。
5. 按「儲存」。

如果左邊有「機構單位」可以選，請選最上層（整個網域），或至少包含會用到 3D 校園的老師和學生。

**完成的樣子：** 該選項顯示為「已開啟」。

---

## 第 2 項：在 Google Cloud 專案啟用 Classroom API

**只做一次**（用當初建立 Firebase 專案的那個帳號）。

1. 開 <https://console.cloud.google.com/>，上方專案選 `xikou-3d-campus`。
2. 左邊選單 →「API 和服務」→「程式庫」。
3. 搜尋 `Google Classroom API`，點進去。
4. 按「啟用」。

**完成的樣子：** 按鈕變成「管理」，頁面顯示「API 已啟用」。

這個 API 免費，不需要升級 Firebase 方案。

---

## 第 3 項：OAuth 同意畫面加上 Classroom 的權限

**只做一次**，同一個 Google Cloud 專案。

1. 左邊選單 →「API 和服務」→「OAuth 同意畫面」。
   （新版介面叫「Google Auth Platform」，權限在左邊的「資料存取權」Data Access。）
2. 按「新增或移除範圍」。
3. 在篩選框分別搜尋並勾選這三個：

| 範圍（scope） | 用途 |
|---|---|
| `.../auth/classroom.courses.readonly` | 讀「我教哪些班」 |
| `.../auth/classroom.rosters.readonly` | 讀每個班的學生名單 |
| `.../auth/classroom.profile.emails` | 讀學生的 email（用來對應 3D 校園的進度） |

4. 按「更新」，再按頁面最下面的「儲存」。

**會看到的提醒：** 前兩個在「非機密範圍」，只有 `classroom.profile.emails` 在「機密範圍」，旁邊有紅色三角形，還要填「您預計如何使用這些範圍？」。原因說明照實寫就好（例如：老師登入後讀自己 Classroom 課程的學生 email，用來對應學生在校園網站的學習進度，只在老師畫面顯示、不另外儲存）。**先不用送審。** 第 4 項把 App 設為信任之後，兩個網域裡的帳號應該不會看到「未經驗證」的警告。這一點我沒有辦法事先保證，要等測試頁實際登入才能確認；如果還是出現警告，到時候再決定要不要送 Google 審查。

**完成的樣子：** 「您的敏感範圍」清單裡有上面三項。

---

## 第 4 項：兩個網域都把這個 App 設為「信任」

**老師網域、學生網域各做一次。** 學生網域第一階段已經設過，這次請進去確認還在，並確認沒有把 Classroom 擋掉。

> 學生網域的帳號登入 console.cloud.google.com 看不到 `xikou-3d-campus`，這是正常的：專案屬於建立它的那個帳號，不用在學生網域找專案。學生網域只要在 admin.google.com 用「用戶端 ID」把 App 加進來就好。

1. 用該網域的管理員帳號登入 <https://admin.google.com/>。
2. 左邊選單 →「安全性」→「存取權與資料控管」→「API 控制項」。
3. 按「管理第三方應用程式存取權」。
4. 看清單裡有沒有這個 App：
   - **有**：點進去 →「變更存取權」。
   - **沒有**：按「設定新的應用程式」→「OAuth 應用程式名稱或用戶端 ID」→ 貼上前面複製的用戶端 ID → 搜尋 → 勾選它 → 選取。
5. 範圍選整個網域（或包含老師、學生的機構單位）。
6. 存取權選「信任」（Trusted）。
7. 按「繼續」→「完成」（或「變更存取權」）。

**另外看一眼：** 同一頁「API 控制項」裡的「管理 Google 服務」，找到「Classroom」，確認它不是「受限制」而且沒有擋掉受信任的 App。

**完成的樣子：** 兩個網域的清單裡，這個 App 的存取權都顯示「信任」。

## 做完之後

跟我說「四項設定做好了」（或哪一項卡住、畫面長怎樣，截圖給我）。我接著做：

1. 一個只有你看得到連結的**測試頁**：用老師帳號登入，列出「我是老師的課程」和每個班的學生名單。
2. 用它確認三件事：
   - 老師網域的帳號讀不讀得到「學生網域管理員開的課」。
   - 學生的 email 讀不讀得到（跨網域有時會被隱藏）。
   - 登入時有沒有出現「未經驗證的應用程式」警告。
3. 都沒問題，才開始做徽章和老師的進度看板。

## 已經決定的事（備忘）

- 顯示名稱用 Google 帳戶名稱（自己的畫面、之後的多人連線都用）。Firestore 的進度資料裡仍然不存姓名，看板上的姓名是當下從 Classroom 讀的。
- 用「簡單版」：Firestore 規則讓老師網域可以唯讀全部學生進度；畫面只顯示「我在 Classroom 是老師、而且進行中的課程」的學生。
- 不用雲端函式，不升級付費方案。

## 還有一件第一階段的事要請你確認

11-05 我改過規則檔 `site/firestore.rules`（進度合併、大小上限）。它不會自動生效，要貼到 Firebase 主控台 →「Firestore Database」→「規則」→「發布」。我這邊沒有你貼過的紀錄，請看一下主控台上的規則第一段註解是不是寫著「只有學校網域、email 已驗證的帳號能存取」。第二階段開工時規則還會再改一次，到時候一起貼也可以。

## 第二階段上線後要做的兩件事（2026-11-11，?v=325）

**A. 發布新版規則**（必做，不然老師進度頁會顯示「讀取失敗」）
1. 用記事本打開 `site/firestore.rules`，全選複製。
2. Firebase 主控台 →「Firestore Database」→「規則」→ 全部取代貼上 →「發布」。
3. 新版第二行註解寫著「第二階段（2026-11-11）」就對了。

**B. 把學生網域的管理者帳號加進 staff 名單**（要讓那兩個帳號看進度才需要）
1. Firebase 主控台 →「Firestore Database」→「資料」→「+ 開始集合」。
2. 集合 ID 填 `staff`。
3. 文件 ID 填管理者的 email，**全部小寫**，例如 `xxx@st.skps.tp.edu.tw`。
4. 欄位隨便放一個，例如欄位 `note`、類型 string、值「電腦老師」→「儲存」。
5. 第二個帳號：在 staff 集合裡「+ 新增文件」，一樣用 email 當文件 ID。
6. 之後要移除權限，刪掉那份文件就好。

老師網域（@skps.tp.edu.tw）不用加，本來就看得到。
